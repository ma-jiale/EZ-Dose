# V2 客户端 UI 覆盖与验收

## 范围与基线

在 `feat/v2-complete-client-ui` 上延续已确认的首页、黑白灰配色、独立 Logo 和 Windows 字体规范。一级导航为工作台 / 患者 / 记录 / 设置；不新增统计大屏。

本轮仅实现 Flutter 客户端 UI、内存状态和本地模拟设备。没有后端、网络请求、真实登录、跨机构鉴权、数据库、串口、蓝牙或摄像头接入。重启应用会恢复虚构初始数据；不能作为真实临床执行或记录凭证。

认证服务未连接时不会接受任意密码伪装登录成功；“进入本机工作区”仅设置当前内存中的操作人。机构选择仅列本机机构，成员编辑不声称具有服务端授权能力。真实权限边界应在服务接入阶段实现。

标签当前提供患者编号查看；打印、扫码图像输入、患者图片导入、真实摄像头采集及物理维护动作需要后续平台适配。辅助数药和校准使用明确标识的本地测试样本，不是实际视觉识别。

## 状态与结构

- `domain/store.dart`：患者、药物、处方快照、任务、逐药状态和操作日志；以 `AppScope` 通知页面更新。
- `domain/machine.dart`：`MachineService` 契约及 `MockMachine`，只使用本地定时器产生进度与反馈。
- `pages/`：患者、执行、结果、记录、设置和账户页面。
- `ui/components.dart`：统一页面、响应式列、表单、空态和状态标签。
- `theme.dart`：八级文字规范、颜色、48px 按钮触控目标。

日期交集计算仅覆盖处方有效日期。跳过不会增加完成数。暂停不算完成；运行中禁止重复开始。结果不明时不能开始或跳过，必须填写人工核对结果。补药保留已完成步骤，只重新处理待补项，并重新核对药盒。任务使用处方拷贝，后续资料编辑不改变历史任务。UI 维护操作在任务进行中锁定。

## 手动验收路径

1. 右上角设备 → 查找设备 → 连接“本地测试设备”。
2. 工作台打开 B-302 → 核对药盒并开始 → 输入 `000001` → 核对药盒。
3. 进入摆药工作台 → 首次药物校准 → 准备/采集/确认 → 核对饭前药盘。
4. 开始分药并二次确认；可暂停/继续。逐药操作，切换用药时机时重新核对药盘。
5. 跳过一项后处理剩余药物，结果必须为待补药；开始补药需重新核对药盒。
6. 设备详情选择“结果不明确”，下一次分药进入人工核对，不出现自动重试；保存核对备注后再继续。
7. 记录页查看结果、独立的待同步状态和操作日志。
8. 患者页新增资料/处方，验证列表和工作台联动；设置页调整默认天数及字号。

自动测试覆盖字体选择、全部页面桌面/平板/窄屏布局、表单保存、设备连接、摆药页面闭环、暂停与补药、处方日期边界、快照隔离、错误药盒和不明结果禁止重放。
