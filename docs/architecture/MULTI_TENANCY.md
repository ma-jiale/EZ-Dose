# 多养老院隔离（待实现契约）

用户可以通过 Membership 属于多家养老院，角色存储在 membership 而不是单一 users.nursing_home_id。
请求认证后，服务端验证用户仍属于选中的养老院，并生成 TenantContext；客户端 tenant ID 仅是选择请求。
所有 tenant-owned 表包含 nursing_home_id，查询/更新/删除从 TenantContext 限定范围。
关联患者、设备、处方和任务时校验同租户；采用租户复合唯一键/外键阻止跨租户引用。
患者编号和设备编号按养老院唯一。全局 User 与租户所属数据分开。

越权验证覆盖列表、详情、写入、导出、同步、附件、历史、搜索与软删除。
测试至少建立 A/B 两个租户，逐个替换资源 ID、嵌套关联 ID 和请求 tenant ID，验证无法泄漏或修改。
PostgreSQL RLS 可以作为纵深防御，不能替代 API 授权；若采用需测试连接池上下文清理。
后台任务和迁移同样必须显式绑定租户，不设置隐式默认全库访问。
平台管理员的跨租户行为单独授权并审计。当前骨架尚未实现上述模型和权限。
